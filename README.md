# Лабораторная работа № 1 — цветовые модели

Локальное веб-приложение на Python без сторонних библиотек. Поддерживает оба варианта задания:

- чётный номер: **CMYK + RGB + HSV**;
- нечётный номер: **CMYK + RGB + HLS**.

## Запуск

Из папки приложения:

```bash
python3 server.py
```

Откройте в браузере **http://127.0.0.1:8765**. Остановка сервера: `Ctrl+C`. Если порт занят: `python3 server.py --port 8766`.

## Что можно показать преподавателю

1. Выберите вариант по чётности номера.
2. В любом из трёх блоков введите точное значение, передвиньте ползунок или откройте палитру.
3. Проследите, как меняются образец, HEX и остальные две модели.
   Под полями показывается формула для модели, которую вы меняли последней.
4. Проверьте граничные случаи: RGB `(0, 0, 0)` — чёрный, RGB `(255, 255, 255)` — белый; HSV/HLS: тон `0°` и `360°` дают один цвет; насыщенность `0%` даёт оттенок серого.

## Суть моделей

**RGB** описывает свет экрана: красный, зелёный и синий каналы от 0 до 255. `(255, 0, 0)` — красный; `(0, 0, 0)` — чёрный; `(255, 255, 255)` — белый.

**CMYK** описывает доли красок в процентах: C — голубая, M — пурпурная, Y — жёлтая, K — чёрная. В упрощённой математической модели:

```text
R = 255 × (1 − C/100) × (1 − K/100)
G = 255 × (1 − M/100) × (1 − K/100)
B = 255 × (1 − Y/100) × (1 − K/100)
```

При переводе RGB → CMYK сначала нормируем `r = R/255`, `g = G/255`, `b = B/255`. Затем `K = 1 − max(r,g,b)` и при `K < 1`: `C = (1−r−K)/(1−K)`, аналогично для M и Y. Для чёрного (`K = 1`) C, M и Y считаются равными 0.

**HSV**: H — тон на цветовом круге от 0° до 360° (0° — красный, 120° — зелёный, 240° — синий); S — насыщенность от 0% (серый) до 100%; V — яркость от 0% (чёрный) до 100%. При `V = 0` цвет чёрный независимо от H и S.

**HLS**: H — тот же цветовой тон, L — светлота от 0% (чёрный) через 50% к 100% (белый), S — насыщенность. В HLS светлота 50% может соответствовать чистому яркому цвету. Поэтому L нельзя считать тем же самым, что V в HSV.

В приложении все преобразования выполняет Python (`server.py`). При изменении любого компонента страница отправляет его значения на `/api/convert` и получает заново рассчитанные модели. Цвет для палитры и HEX округляется до 8 бит на канал. Выбранные значения исходной модели сохраняются без замены: например, при нулевой насыщенности можно менять H и видеть, что серый цвет остаётся тем же.

## Как устроен код

1. `app.js` строит поля по описанию моделей в `MODELS`. После изменения числа или ползунка он собирает значения одного блока и посылает JSON-запрос на `/api/convert`.
2. `server.py`: `parse_components()` проверяет диапазон и тип данных. Каналы RGB должны быть целыми числами от 0 до 255; проценты и тон могут быть дробными.
3. `source_to_rgb()` приводит выбранную модель к RGB с каналами от 0 до 1. Для CMYK используется формула выше, для HSV и HLS — функции стандартного модуля Python `colorsys`.
4. `convert()` из полученного RGB рассчитывает все остальные модели. Для CMYK сначала берёт `K = 1 − max(r,g,b)`; для HSV и HLS снова использует `colorsys`. В конце RGB округляется до целых каналов для HEX.
5. Сервер возвращает JSON. `render()` в `app.js` обновляет образец, поля и формулу. Номер запроса не даёт более старому ответу перезаписать новый цвет.

Например, для `RGB(255, 128, 0)` нормированные каналы равны `1`, `128/255 ≈ 0,502`, `0`. Тогда `K = 0`, `C = 0`, `M ≈ 49,8%`, `Y = 100%`. В HSV тон ≈ `30,12°`, насыщенность и яркость равны `100%`. В HLS тон такой же, светлота `50%`, насыщенность `100%`. Это один и тот же оранжевый цвет, записанный разными координатами.

Это учебная модель CMYK без цветового профиля конкретного принтера и бумаги; реальные цвета печати могут отличаться.
